# firmware/hex - the 13 built programs

This folder is where `tools/Build-All-HEX.bat` copies the finished HEX files.
It is the folder you take to the lab.

```
firmware/hex/
  01_led_blink.hex
  02_led_patterns.hex
  03_switch_led.hex
  04_seg7_counter.hex
  05_timer0_second.hex
  06_square_wave.hex
  07_ext_interrupt.hex
  08_uart_echo.hex
  09_uart_commands.hex
  10_adc_7seg.hex
  11_adc_lcd.hex
  12_industrial_monitor.hex
  13_selftest.hex
```

---

## Why this folder is committed when every other build artifact is not

`.gitignore` ignores `*.hex` and `Objects/`, because those are regenerated by
every build. **This folder is the deliberate exception**, for three reasons:

1. The HEX files are the deliverable. A reviewer can flash them without owning a
   Keil licence, which matters because the free C51 compiler is capped at 2 KB.
2. They are small - about 4 KB each, roughly 50 KB for all thirteen.
3. They are evidence. A commit containing the built binaries proves the sources
   compiled, which a screenshot does not.

The rule in `.gitignore` is:

```
*.hex
firmware/hex/*
!firmware/hex/README.md
!firmware/hex/*.hex
```

The negations must come **after** the ignores, and the directory may not be
excluded as a whole - that is why the pattern is `firmware/hex/*` and not
`firmware/hex/`. If the folder itself is ignored, no file inside it can be
re-included.

---

## How the files get here

You do not copy them by hand. Run the build script:

```
tools\Build-All-HEX.bat
```

It builds all 13 projects, checks each HEX for the reset jump at address 0, and
copies every good one into this folder. See `docs/SOFTWARE_RUNBOOK.md` section 3.

---

## Before you commit them

Check each file is real. Open one in Notepad:

| Check | Expected |
|---|---|
| first line | starts with `:0300000002` (an LJMP at address 0) |
| last line | exactly `:00000001FF` |
| size | 1 to 6 KB |

A file that fails the first line will not boot. Rebuild that project rather than
committing it.

---

## Committing and pushing

```bash
git add firmware/hex/*.hex firmware/hex/README.md
git status --short                 # should list 13 files as added
git commit -m "Add built HEX files for programs 01-13"
git push
```

If the files still do not appear, the ignore rule is winning. Diagnose it with:

```bash
git check-ignore -v firmware/hex/12_industrial_monitor.hex
```

- No output means the file is **not** ignored, and `git add` will work.
- Output naming a `.gitignore` line means that line is still excluding it.

Force-add works as a one-off, but fix the rule instead - a forced file is easy to
lose track of:

```bash
git add -f firmware/hex/12_industrial_monitor.hex
```

---

## If a program came back OVER LIMIT

Programs 09, 12 and 13 usually exceed the 2048 byte free-compiler cap. Either
build them with `-Small -LX51`, build them on a licensed machine, or commit the
ten that do fit and state plainly in the report that the remaining three were
built with a licensed toolchain. Do not commit a HEX from a failed build - the
build script will not copy one, so an empty or missing file means the build
itself failed.

---

## What must never be committed here

- `firmware/keil/Objects/` or `Listings/` - build intermediates, regenerated.
- `.uvguix*` and `.uvoptx` - per-user editor state, machine specific.
- Anything from `firmware/keil/Logs/` - transient build logs.

All three are already covered by `.gitignore`.
